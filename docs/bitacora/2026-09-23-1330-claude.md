# 2026-09-23 13:30 — Claude — Cobro: cliente fijo salvo para el administrador (en 59.07, sin publicar)

Continúa `2026-09-23-1300-claude.md`, que dejó la ventana de cobro renovada y sin publicar.

## Solicitud del dueño
«Automatizar la ventana cobros que no se pueda cambiar el cliente solo el administrador».

## Diagnóstico
- Tanto Vender como Factura eligen el cliente antes de cobrar, en «Facturar a» (`nxFacCliToggle`, que guarda `_factCli`).
- `nxPosCobrar` ya recibe ese cliente de forma automática (campo oculto `#posCliId`).
- Aun así, la ventana de cobro dejaba a cualquier rol cambiar o quitar el cliente, con `nxPosCobroCliToggle` y `nxPosCobroCliClear`.

## Cambios (`parches-pos.js`, `studio-brand-theme.css` §17)
- Nuevo `_posCobroCliEditable()`: devuelve verdadero solo si `rolEfectivo() === 'admin'`.
- **Roles distintos de administrador** (gerente, cajero, vendedor):
  - el cliente se ve como una ficha fija con candado, sin botón ✕ y sin abrir el buscador;
  - si se llama a `nxPosCobroCliToggle`, sale el aviso «Solo el administrador puede cambiar el cliente al cobrar»;
  - `nxPosCobroCliClear` no hace nada;
  - si queda saldo a crédito sin cliente, el aviso dice que el cliente se elige en «Facturar a» antes de cobrar.
- **Administrador:** todo sigue como antes (cambiar y quitar).
- «Facturar a» en Vender y Factura no cambia.
- La vista previa de rol del administrador (`_rolPreview`) respeta el bloqueo.
- Se agregó una nota en `version.json` 59.07.

## Riesgos
- El bloqueo es de pantalla. El RPC de venta sigue aceptando el `cliente_id` que se le envíe.
- Si el dueño quiere que el gerente también pueda cambiar el cliente, basta con agregar `'gerente'` en `_posCobroCliEditable`.
