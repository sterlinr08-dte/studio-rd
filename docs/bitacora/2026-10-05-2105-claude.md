## Cambios

### `supabase/48_codigos_automaticos.sql` (NO APLICADA)
- **Artículos:**
  - disparador `trg_zcodigo_pos_productos`: si no trae código, pone el siguiente `PRD-00xxxx` (el mayor PRD de la organización + 1);
  - al editar con el código vacío, conserva el que tenía;
  - el código escrito a mano se respeta;
  - el nombre empieza por `trg_z` para correr después de `trg_org_pos_productos`, que pone la organización;
  - índice único `pos_productos_codigo_unico` (organización + código sin distinguir mayúsculas);
  - los 157 códigos viejos no se tocan.
- **Empleados:**
  - nueva columna `codigo`;
  - los 16 actuales se numeran `001`…`016` por fecha de ingreso, solo la primera vez;
  - disparador `trg_zcodigo_rrhh_empleados`: un empleado nuevo recibe el siguiente número;
  - índice único `rrhh_empleados_codigo_unico`.
- Los números se calculan en el servidor con un candado por organización (`pg_advisory_xact_lock`): dos altas al mismo tiempo no reciben el mismo.

### Pantalla (`parches-pos.js`)
- **Ficha del artículo:** el campo Código dice «Automático (PRD-…) o escríbelo».
  - Al guardar, el aviso muestra el código asignado.
  - Si el código ya existe, dice «Ese código ya lo tiene otro artículo» y no cierra la ficha.
- **Recursos Humanos → Empleados:**
  - la lista va en orden de código;
  - cada empleado muestra su código en una etiqueta;
  - la ficha muestra el código en el título;
  - al guardar un empleado nuevo, el aviso dice «Código 004».
- **Ajustes → Usuarios → «Empleado vinculado»:** las opciones muestran «001 · Nombre · Puesto», así el buscador de 59.88 encuentra por código.
  - Si la columna todavía no existe, la lista se lee sin ella.
- `APP_VERSION` sube a 59.89; también `version.json`.
